# Format spec — how a lesson card is written to disk

`schema/lesson-card.v1.json` fixes *what* a card contains. This file fixes *how it is written*, so
two runs that found the same things produce byte-identical files and a diff between two cards shows
content drift only.

## The file

- One card per input, UTF-8, LF line endings, exactly one trailing newline.
- Named `cards/<input-stem>.card.json`.
- JSON, 2-space indent, no tabs.

## Key order is part of the contract

Top-level keys appear in the order given by `fieldOrder` in the schema:

```
schema · profile · generated_utc · source · title · speakers ·
claims · definitions · numbers · entities · steps · unmapped · coverage
```

Not alphabetical, not insertion order — that exact order, in every card, regardless of input.
Nested objects follow the key order declared in their `required` array. `quote` objects are always
`{"text": …, "span": …}` and spans are always `{"start": …, "end": …}`.

This is why the shape test run by `checker/shape-diff.mjs` can be a literal field-by-field diff: if
key order were free, every diff would be noise and the "same shape every time" claim would be
uncheckable.

## Absent values

The literal string `not in source`, lower case, single spaces, no punctuation. It is a JSON string
in every position it can appear — including where the field would otherwise have been an array.

## Spans

- Byte offsets into the UTF-8 encoding of `source.file`, half-open `[start, end)`.
- `start` and `end` are integers; `start < end`; `end <= source.bytes`.
- Offsets are **byte** offsets, not UTF-16 code-unit offsets. A card generated by a JavaScript
  producer that used `String.prototype.slice` on a decoded string will disagree with this spec on
  any input containing a non-ASCII character, and the verifier will catch it.

## Text

Quote `text` is copied out of the input unchanged: original casing, original punctuation, original
whitespace, original spelling — including transcription artefacts. It is **not** trimmed,
**not** re-wrapped, and **not** unicode-normalised. JSON escaping is the only transformation
applied, because JSON requires it.

## Numbers

`coverage.pct` is a JSON number rounded to two decimal places. `covered_bytes` and `total_bytes` are
integers. `duration_seconds` is a JSON number or the absent marker.

## Who may produce a card

Either producer is legitimate, and the verifier does not know or care which ran:

1. **The folder as a prompt.** Drop this folder into a Claude project; `identity.md`, `rules.md`,
   `examples.md` and this `reference/` are the instructions. The model emits a card.
2. **`checker/convert.mjs`.** A deterministic reference implementation that extracts spans
   mechanically and can, by construction, only emit text it cut out of the input.

`checker/verify-traces.mjs` is the gate over both. That separation is the point of the design: the
contract is enforced on the artifact, not on the goodwill of whatever produced it.
